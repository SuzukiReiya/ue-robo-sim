# ue-robo-sim

Unreal Engine 5.6を使う、遅延・共有制御・自動制御の検証用ロボットシミュレータです。
AP5の「C++でシーンを生成し、PowerShellでビルド・マップ生成・起動する」構成を基に、独立したプロジェクトとして作成しました。破壊・変形機能は含みません。

**現在は検証用実装です。高精細PBR材質・屋内照明について、Windows / UE 5.6上での描画確認はまだ実施していません。実機相当の光学特性やリアルタイム性能は保証しません。**

## モジュール構成（今回の変更）

```text
キーボード / 操縦入力
  ↓ SimKeyboardInput（UEキー状態取得）
  ↓ SimControl::toCommand（キー状態→正規化指令）
  ↓ SimControl::CommandRouter（手動 / 共有 / 自動の制御裁定・指令遅延）
  ↓ SimVehicle（機体プラント・移動・接触）
  ↓ Unreal Engineのシーン（SimEnvironment）
  ↓ SimVideoPipeline（機体カメラ・映像遅延・PNG出力）
  ↓ SimHUD（操縦者画面のみ表示）
```

共有／自動制御のアルゴリズムは`SimControl.h`の指令裁定へ追加する想定です。`SimVehicle.h`と`SimVideoPipeline.*`は制御方式を知らず、機体へ加える指令と撮影対象のActorだけで動作します。UDP入力はCommandRouterの外部入力口に接続し、画面用の遅延は機体の制御ループへ混ぜません。実験用真値は別CSVへ記録します。

[各モジュールの責務と拡張方針](docs/構成と拡張方針.md)を参照してください。

## テクスチャと屋内環境

- フィールド内は20m四方のまま。プラダン風の板柵、異なる色の継ぎ目・柱・小障害物、塗装の擦れを追加。
- フィールド外には34～36m規模の屋内ホールとして、外周壁、天井、梁、支柱、備品、照明パネルを配置。
- `Scripts/GenerateTextures.py`が**2048×2048**のBase Color／Normal／Roughnessを3種類の表面（プラダン・コンクリート・床）ごとに自動生成。外部画像・pip依存はありません。
- `Scripts/CreateMap.py`は既存の256px用アセットを再利用せず、新規の`*_PBRv2`アセットを生成して**Default Lit**で表示します。表面の凹凸と反射粗さを別マップで制御します。
- 再現性のため画像の乱数seedは固定です。テクスチャの模様自体は反復しますが、一様な格子だけではありません。画像処理研究で重要な対象の輪郭や色と背景の混同は別途評価してください。
- カメラ画像は**640×360・1～60fps（初期20fps）**。シーン側はDefault Lit＋方向光で凹凸と陰影を表現します。赤い追跡対象は認識試験を維持するため単色Unlitのままです。

更新後は`git pull --ff-only`して`Scripts/BuildAndRun.ps1`を再実行してください。初回は2048pxのPNG計9枚を生成・UEへ取り込むため、従来より処理時間・容量を消費します。2回目以降は`/Game/Generated/M_*_PBRv2`が揃っていれば再生成を省略します。

**注意**: 照明は固定した仮の屋内条件です。Unlitの旧版とは色・明暗が変わるため、画像認識の結果を比較するときは環境条件を分けて記録してください。旧テクスチャを残すため、以前のUEアセットも引き続き保存されます。

**初回の生成だけを確認する場合**:

```powershell
.\Scripts\BuildAndRun.ps1 -BuildOnly
```

正常なら`.local/logs/map.log`内に`ROBOT_SIM_MAP_READY: PBR v2`が出ます。表示を確認した後に通常起動してください。

## 一時停止と操作割り当て

**Esc**でシミュレーションを一時停止し、操作設定画面を表示します。画面の「保存して再開」「保存せず再開」「初期値に戻す」「終了」から操作できます。Escをもう一度押すか「保存せず再開」で元のシミュレーションへ戻ります。

- 設定できる操作: **前進・後退・左平行移動・右平行移動・左旋回・右旋回・射撃**（各1入力）。同じ入力を複数の操作に設定すると保存できません。
- 対応する入力: WASD・Q/E/R/F/Z/X/C/V/I/J/K/L・Shift・Ctrl・矢印キー・マウス移動の上下左右・左右クリック。
- マウス移動は**移動した瞬間の方向と量**を読み取る方式です（トラックボール的な操作）。左右・上下の感度を設定画面で変更できます。手を止めると指令もゼロになります。マウスを右へ動かし続けると右旋回する、といった使い方ができます。
- Esc（メニュー）、Space（非常停止）、1/2/3（モード切替）、F1（デバッグ）は予約キーです。
- 初期設定: W=前進、S=後退、A/D=左/右平行移動、マウス左右=旋回、**マウス左クリック=射撃**。
- 設定は\`Saved/Config/InputBindings.json\`に保存し、次回起動時にも読み込みます。設定が無効なら初期値へ戻します。
- 射撃は暫定的な**前方レイキャスト**（4発/秒、命中判定と短いデバッグ線を描画）です。実弾の弾道・発射速度・重力・BB弾の特性は未実装です。射撃の指令にも操縦入力と同じ指令遅延を適用します。
- 一時停止中はシミュレーション時刻、機体運動、対象移動、画像取得・遅延処理が停止します。設定メニューの入力は機体へ届きません。復帰時は古い入力キューを破棄し、外部UDPの滞留データを捨てます。

**一時停止はOS／UEプロセス全体の停止ではありません。** メニュー描画と入力受付は継続します。実験の再現性を比較する場合は一時停止時間を別条件として扱ってください。

## 操作割り当て・追加シミュレーション設定

Escの設定画面をスクロール式に変更し、選択プルダウンは暗い背景でも読める白文字に調整しました。

初期操作は**W/S＝前後、A/D＝左右平行移動、マウス左右＝左右旋回、左クリック＝射撃**です。平行移動は機体の向きを変えず、横方向の速度指令として機体モデルに入ります。前進や旋回と同時に実行できます。すべてのアクションに「なし」を選べます。同一入力を複数のアクションへ割り当てることはできません。

設定画面の調整項目：

| 項目 | 初期値 | 内容 |
|---|---:|---|
| マウス左右の操作感度 | 0.0833/px | 横方向マウス移動による操作指令の大きさ |
| マウス上下の操作感度 | 0.0833/px | 縦方向マウス移動による操作指令の大きさ |
| マウスボタンの操作強度 | 1.0 | ボタンを移動／旋回へ割り当てたときの入力強度（射撃判定には影響しない） |
| 機体の慣性揺れ | 1.0度 | 前後／左右の加減速と旋回で生じる姿勢揺れ。カメラと射線に共通適用 |
| 射撃ごとのブレ | 0.8度 | 発射時の射線分散と反動。反動はカメラにも残り減衰する |
| タイヤの滑り | 0.15 | 0＝グリップ高／1＝滑り大。機体速度が進行方向に追従する速さを変える |
| 操作指令ラグ | 100ms | 操縦指令の到達遅延。射撃要求にも適用 |
| 映像表示ラグ | 100ms | 操縦者向けカメラ映像の遅延。機体内センサ画像には適用しない |
| 表示FPS | 20fps | カメラ更新頻度（1～60fps、実描画負荷によって下回る） |

**設定の保存先**は従来どおり `Saved/Config/InputBindings.json` です。旧版の5種類の割り当てから読み込めます。旧初期値のW/S/A/Dを使用していた場合は新しい初期値へ更新し、旧版でカスタマイズ済みの場合は既存の旋回設定を優先して横移動を未割当で読み込みます。

実験開始時の設定は `Saved/Experiments/<実行ID>/settings.json`、実行途中でEscから変更した値は `parameter_changes.csv` に記録します。起動コマンドに `-CommandDelayMs`・`-VideoDelayMs` を明示した場合、初回起動時はコマンドライン引数を優先します。

**モデルの制約**：機体揺れは接触力学を解くものではなく、加減速から求める仮想車体姿勢です。カメラと射線の向きへ反映しますが、車体メッシュ全体の変形やサスペンションは未実装です。タイヤ滑りも平面速度の一次遅れ近似であり、グリップ限界・個々のタイヤ力は未再現です。物理条件の検証には別途実測との校正が必要です。

## 旋回慣性と敵ロボットのヒットパネル

- **旋回慣性**：従来の並進滑りとは別に、角速度の追従・減衰時定数を設定します。初期450ms、Esc設定から0～1500msで変更できます。入力を離しても機体が短時間旋回を続けます。
- **敵ヒットパネル**：添付`GroundHitPanelModule.step`に基づく約90×90×19mmの低ポリゴンメッシュ（約500三角形）を4方向へ固定。生成用OBJは`Saved/GeneratedMeshes/GroundHitPanelModule.obj`です。編集時の追加CADアプリやpipパッケージは不要です。
- **取付角度**：公式ATTRACTSルールブック v1.0・III-3.3（35～36ページ）に沿い、パネル面を**地表面から75°**に固定。機体前後・左右で対向配置します。パネル中心の高さはすべて**150mm以下**です。
- **高さプリセット**：低6cm／標準9cm／高12cm／上限付近14.5cm／段違い（前後12cm、左右6cm）。Escから変更し、再起動後も保存されます。前後左右の相対位置・角度は稼働中に変化しません。
- **小型車体**：ヒットパネルが車体に埋まらないよう敵を18cm角の低いシャーシへ変更。自身も20×18cm程度の小型ボディとし、カメラ・射出口を床上約12～14cmに移設しました。パネルは機体Rootへ追従します。
- **被弾判定**：パネル前面の専用レイキャスト面に当たると`SIM_FIRE`ログに「パネル被弾=はい」と出ます。F1診断と`truth.csv`にも命中数を記録します。現在は弾道を用いない試験用判定です。

**ルール適合上の注意**：公式にはパネル面から勾配60°で押し出した範囲の非遮蔽も必要です。今回の配置は周囲に機構を設置しない設計ですが、60°非遮蔽の体積検査を自動化したものではなく、**実機の公式車検への適合を保証するものではありません**。STEP形状は描画用に簡略化しており、被弾・遮蔽判定は別途近似形状を使用します。固定75°で取り付け、稼働による±30°の許容規定は使用しません。

初回起動時、`map.log`に`ROBOT_SIM_PANEL_MESH_READY`が出ればメッシュ取込済みです。OBJインポートに失敗した場合は`ROBOT_SIM_PANEL_MESH_FALLBACK`が記録され、表示だけ簡易90mm角の箱に切り替わります。

## 初期版の機能

- 20m四方のテクスチャ付きフィールド、屋内ホール、自機、赤い移動対象、障害物をC++で生成。
- WASD操作と一人称カメラ映像。操縦者画面は遅延させた画像だけを表示。
- 指令遅延と映像遅延を独立設定。揺らぎ・欠落率・乱数seedも設定可能。
- 手動／共有／外部自動制御。共有は手動と外部指令の重み付き合成。
- 120 Hzの運動更新、最大1.5 m/s・120度/s、時定数150 msの一次遅れ。
- 設定可能な1～60fps、640×360、画角90度のカメラ。描画FPSが低いと取得FPSも低下。
- 機体側カメラ画像をPNGで外部出力（任意）、localhost UDPで外部指令受信。
- 実験設定と機体真値・各指令のCSV記録。記録した指令の再送サンプル。
- 正解座標を使わず赤い画像領域から向きを補正するPythonサンプル。

`main`は競技非依存の基盤とします。競技固有の寸法・ルール・モデルは、後から `feature/attracts` などの専用ブランチに追加する方針です。現状の寸法は競技公式値ではありません。

## 必要環境

- Windows 11、Windows PowerShell 5.1またはPowerShell 7。
- Unreal Engine 5.6.x。AP5用に導入済みのUEを利用できます。
- Visual Studio 2022のC++ビルドツール、対応するWindows SDK。
- Python 3.10以降は外部サンプル利用時のみ必要。

UE本体はEpic Games Launcherから導入してください。ライセンスの同意・アカウント登録は自動化しません。

## ビルド・起動

```powershell
git clone https://github.com/SuzukiReiya/ue-robo-sim.git
cd ue-robo-sim
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Scripts\BuildAndRun.ps1 -EngineRoot "D:\Epic Games\UE_5.6"
```

実際のUE導入先を指定してください。省略時は環境変数`ROBOT_SIM_UE_ROOT`、続いて標準パス`C:\Program Files\Epic Games\UE_5.6`を使用します。
起動方式は開発用のStandalone Gameです。配布用exeのパッケージ化はまだ用意していません。
マップと材質を初回生成するため、手動のエディタ配置は不要です。

```powershell
# 遅延なしの基準条件
.\Scripts\BuildAndRun.ps1 -CommandDelayMs 0 -VideoDelayMs 0
# 指令100ms、映像200ms、揺らぎ±30ms、欠落率2%
.\Scripts\BuildAndRun.ps1 -CommandDelayMs 100 -VideoDelayMs 200 -JitterMs 30 -LossRate 0.02 -Seed 12345
# ビルド・マップ生成のみ
.\Scripts\BuildAndRun.ps1 -BuildOnly
```

起動後、画面をクリックしてキーボードのフォーカスを与えます。

| キー | 動作 |
|---|---|
| W / S | 前進／後退（初期割り当て） |
| A / D | 左平行移動／右平行移動（初期割り当て） |
| マウス左右移動 | 左右旋回（初期割り当て） |
| マウス左クリック | 射撃（初期割り当て） |
| 1 | 手動 |
| 2 | 共有制御（外部指令との合成） |
| 3 | 外部自動制御 |
| Space長押し | 検証用の遅延なし非常停止 |
| F1 | 研究用の状態表示を切替（初期状態は非表示） |
| Esc | 一時停止・操作設定画面（再度押すと再開） |

モード切替では指令キューを消去し、新しい入力を待ちます。機体速度は時定数に従って変化します。Spaceのみ速度も即座にゼロにします。Escでは進行が停止し、設定画面の操作はゲーム内の入力として扱いません。

**移動確認**: まず `1` で手動モードにして `W` を1秒ほど押してください。`S` は後退です。指令遅延（既定100ms）と時定数（150ms）があるため、押してすぐには動きません。`F1` を押すと「手動前後入力／適用前後入力／速度／XY座標／移動遮断」が表示されます。`3`（自動モード）ではW/S入力は適用されません。`2`（共有モード）では外部指令と合成するため、移動速度が低下する場合があります。

旧版は床にも衝突判定を設定していましたが、平面運動のSweepと床面の接触判定が干渉する可能性があるため、床を表示専用に変更しました。壁・障害物の衝突判定は維持しています。
**映像解像度について**: カメラの640×360画像を1280×720のウィンドウに拡大表示するため、画素が粗く見えるのは意図的です。カメラ更新は設定画面で1～60fpsに変更できます。背景・床・壁は高精細PBRへ更新しました。実機の光学ノイズ・レンズ特性・圧縮劣化は未再現です。

外部指令が250ms（シミュレーション時間）届かなければ、自動モードは停止指令、共有モードは手動に戻ります。手動指令も最終到着から250msでゼロにします。

## 画像を使う外部制御

```powershell
# 端末1: 機体側画像を出力して起動
.\Scripts\BuildAndRun.ps1 -ExportFrames
# 端末2: リポジトリ直下で実行
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r Clients\requirements.txt
.\.venv\Scripts\python.exe Clients\color_tracker.py
```

UEで`2`または`3`を押すと、赤い対象が画面中央へ寄るよう旋回指令を出します。これは画像入出力を確認する色抽出の比較器であり、学習済み追跡モデルではありません。自動モードでは前進しません。共有モードの既定重みは0.5で、外部の前進指令がゼロなので手動前進も半分になります。`-SharedWeight`で変更できます。

画像出力は操縦者向け映像遅延を適用する前の画像です。機体内処理を想定しています。PC遠隔処理の画像転送遅延や実機の通信は未実装です。

## 記録・再実行

`Saved/Experiments/<実行ID>/settings.json`と`truth.csv`へ設定と記録を保存します。真値CSVは評価者専用で、追尾サンプルは読みません。
同じ設定・seedで条件を再実行できますが、入力タイミング・描画・OSスケジューリングまで決定的にはなりません。

```powershell
# UEを再起動して3（自動）へ切替後、過去の適用指令を送る
python Clients\replay_commands.py Saved\Experiments\<実行ID>\truth.csv
```

この再送は適用指令を壁時計に従って送り直す簡易方式です。元の通信遅延を再適用せず、相手の位相や機体軌跡の完全一致も保証しません。録画再生・状態スナップショット・厳密な決定的リプレイは今後の実装です。

## 検証と制約

```bash
g++ -std=c++17 -Wall -Wextra -Werror Tests/test_core.cpp -o /tmp/test-core
/tmp/test-core
python3 -m py_compile Clients/*.py Scripts/*.py
python3 Tests/test_textures.py
```

GitHub ActionsはC++基盤テストとPowerShell構文確認を行います。UE本体のビルドは含みません。AP5のself-hosted runnerがリポジトリ単位で登録されている場合、このリポジトリからそのまま利用できるとは限りません。

- ロボットの車輪接触・滑り・坂道・転倒は未実装。平面の運動学モデルです。
- 並進はSweepで接触を扱いますが、旋回の形状Sweepは未実装。精密な接触評価には使えません。
- カメラの露出・材質は画像追跡がしやすいよう固定化した仮設定。フォトリアルなモデル、圧縮劣化、レンズ歪み、実機との校正は今後対応します。
- PNG出力は同期GPU readbackを行うため、フレーム時間を増加させます。高速な画像認識の性能評価には、非同期readback・共有メモリ等への置換が必要です。
- 設定した遅延にフレーム量子化・描画・readbackの時間が加わります。遅延0は物理的な入出力遅延ゼロを意味しません。
- 1フレーム250msを超える停止では超過時間を破棄し、`SIM_OVERRUN`を出します。その試行は実時間の遅延比較から除外してください。
- 画像保存は最新2枚のみ。全フレームの収録・認識結果の記録・自動集計は未実装です。
- カメラ停止時は最終画像を保持します。研究表示で画像経過時間を確認できます。

起動ログは`.local/logs/`、UEログは`Saved/Logs/`です。
初回Windows検証の手順は[検証チェックリスト](docs/検証チェックリスト.md)、通信仕様は[外部接続仕様](docs/外部接続仕様.md)を参照してください。
