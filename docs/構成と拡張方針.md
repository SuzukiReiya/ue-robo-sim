# シミュレータ構成と拡張方針

## 原則

- **入力機器**・**操作解釈**・**制御裁定**・**機体プラント**・**映像取得/伝送**・**操縦者表示**を分離する。
- 共有／自動制御には対象真値を渡さない。真値は評価ログのみ。
- 映像遅延とコマンド遅延は別々に加える。カメラから機体内の制御器へ渡す画像に操縦者向け映像遅延を適用しない。
- 物理・映像の実験を比較する場合、テクスチャ・乱数seed・照明条件を固定する。

## データの流れ

```text
UE入力 → FSimKeyboardInput::Read() → RawInput
                                      ↓
                   RobotSim::mapInput() → CommandRouter::submitActions()
                         ├ InputBindings + Tuning : デバイス操作 → 前後・横・旋回・射撃
                         ├ DelayQueue : 指令遅延
ローカルUDP外部制御 → submitExternal() ───┤
                         └ resolve() : 手動/共有/自動 + タイムアウト
                                      ↓ Command(throttle, turn, strafe) + 射撃要求
                             FSimVehicle::Advance()
                                  120Hz XY運動
                                      ↓
               UEシーン ← FSimEnvironment::Build()
                                      ↓
                URobotVideoPipeline（640×360 / 1～60fps）
                         ├ 撮影→PNG出力（任意・未遅延）
                         └ 映像キュー→表示遅延
                                      ↓
                                ASimHUD表示

別系統: 機体位置・速度・コマンド真値 → truth.csv
```

## 操作割り当て・一時停止

Escの設定画面は`USimSettingsWidget`が持つ。UEキー・マウスの生入力は`FSimKeyboardInput`から`RobotSim::RawInput`へ変換し、`SimInputBindings.h::mapInput`が前後・左右移動・旋回指令・発射要求へ変換する。指令は`CommandRouter`で手動／共有／自動の裁定と指令遅延を適用した後、`FSimVehicle`と`FSimWeapon`へ渡す。カメラや機体のクラスは入力デバイスやメニューに依存しない。

設定は`Saved/Config/InputBindings.json`に保存し、ゲームの外部制御・評価ログとは分離する。設定の重複・予約キーは拒否する。一時停止はUE全体のTick停止ではなく、GameModeのシミュレーション時間積分と画像更新を停止する実装。再開時に遅延済み指令キューと滞留UDPを破棄する。

射撃は現状レイキャストの試験用モデルであり、実BB弾の物理や遅延は再現していない。ただし発射要求自体は操縦指令遅延を経由する。

## モードと安全性

- `1` 手動：遅延した操縦指令のみ。
- `2` 共有：有効な外部指令があれば重み付き合成、なければ手動。
- `3` 自動：有効な外部指令のみ。期限切れならゼロ指令。
- 手動・外部の指令有効期限は各250ms。モード切替で手動遅延キューを消去。
- Space非常停止は遅延を適用しない例外で、車両の速度も即時ゼロとする。
- 現在の自動制御はUDP入力を受けるだけで、UE内に画像認識モデルは搭載していない。

## テクスチャと性能評価に関する注意

現在は板・コンクリート・床ごとに**2048×2048のBase Color・Normal・Roughness**を固定seedで生成する。旧256pxアセットとは別名の`*_PBRv2`で取り込み、Default Lit材質を使う。生成用PNGは`Saved/GeneratedTextures/`へ出力し、同じバージョンと画像サイズならキャッシュを利用する。`M_Robot`は識別対象のため単色Unlitを維持する。

本実装は初期的なPBR近似であり、実物を撮影・計測した材質ではない。カメラの画素数は従来どおり640×360、最大60fps（設定可）。実機の撮像ノイズ、被写界深度、レンズ収差、ローリングシャッター、照明変動は含まない。照明は屋内固定の主光・補助光と弱い暗部補助成分であり、正確なグローバルイルミネーションではない。研究比較時は材質版、照明、seedを条件として記録する。

将来の材質変更ではアセット名のバージョンを更新し、`SimEnvironment.cpp`の参照先も切り替える。既存`M_*_PBRv2`は同名なら再利用されるため、コードだけを書き換えても既存uassetへは自動反映されない。

屋内形状は現状仮設定で、競技規定寸法を意味しない。現時点の物理モデルは平面走行で、車輪接触や旋回時の衝突Sweepは未実装。

## 可変シミュレーション条件

`SimTuning.h`でマウス感度、ボタン入力強度、車体慣性揺れ、射撃反動、タイヤ滑り、指令遅延、映像遅延、カメラFPSを保持する。車体の揺れは運動モデル`SimVehicle.h`から姿勢差分を出力し、`SimVideoPipeline`と`SimWeapon`へ同一の差分を適用する。射撃による反動は`SimWeapon`で減衰し、カメラ姿勢にも合成する。

タイヤ滑りは平面ワールド速度の応答時定数を変える近似であり、タイヤ接地力の本格モデルではない。変更時は`parameter_changes.csv`へシミュレーション時刻を付けて記録する。制御入力の正解情報へのアクセス制約は従来どおり。

## 公式ヒットパネルを使用した研究用場面

追加した`SimHitPanels`は入力・操縦モード・映像遅延と独立している。敵車体のSceneComponentルートへ4枚のパネルを親子付けし、初期位置と姿勢を固定する。高さプリセットのみEsc画面から変更できる。形状は添付のSTEPを解析して量子化・簡略化した三角形メッシュを`GenerateHitPanelMesh.py`でOBJに復元し、`CreateMap.py`がUE静的メッシュとして取り込む。OBJが読み込めない環境では90mm角の簡易パネルへフォールバックする。

取付角は75°、中心高さは150mm以下、対象車体は初期寸法300mm角以下を意図した18cm角。参考文書：ATTRACTSルールブック v1.0・III-2.1（34ページ）、III-3.3（35～36ページ）。面から60°の非遮蔽体積と、他部品の実機寸法の完全自動検査は未実装。可視化はCAD低ポリゴンメッシュ、被弾判定は独立したBoxComponentで、シミュレータ外での車検適合は主張しない。

旋回角速度は`SimCore.h::Drive::step`に独立した時定数を指定し、左右並進の滑り係数`tireSlip`とは混同しない。旋回の残留角速度は自機カメラと射線に同一のActor姿勢変化として伝播する。
